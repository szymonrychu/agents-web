Lessons that outlive a session. Newest first.

## 2026-10-27

- markdown-rendering-in-chat (D1-D4, D7, D8, D13): chat text renders through `ChatMarkdown` (`src/chat/Markdown.tsx`), react-markdown 10.1.0 with remark-gfm 4.0.1 and remark-breaks 4.0.0 (tilde ranges), the synchronous default `Markdown` component. Why react-markdown: it builds React elements, so every element maps to MUI and the theme through `components`, and it is safe by default; markdown-to-jsx renders raw HTML unless told not to, marked plus DOMPurify needs `dangerouslySetInnerHTML` and cannot map to MUI. Raw HTML stays text: react-markdown's default is kept (no `skipHtml`, no rehype plugin), so `hello <b>` shows literally. Links keep the default `defaultUrlTransform`: a kept URL opens in a new tab with `rel="noopener noreferrer"`, an unsafe one (`javascript:`, `data:`) comes back as `''` and the mapped link renders with no `href` and no `target`, fragment-only links (GFM footnotes) stay in-page. Images never render an `img` (no remote load from message text): a link to the URL labelled with the alt text (the URL when alt is empty), the plain alt text when the URL was dropped or the image sits inside a link (no nested anchors). Fenced code blocks take their text and `language-<name>` class from the hast `node` of `pre` and render a caption label plus plain text, no highlighter. remark-breaks keeps single newlines as `<br>`, so paragraphs use normal white-space with `overflowWrap: 'anywhere'`. Bundle (`npm run build`, main chunk): before 1,194.11 kB (gzip 348.74 kB); after adding the dependencies the build is unchanged until a row imports `ChatMarkdown` (tree-shaken); with `ChatMarkdown` in the bundle (measured through a temporary import in `main.tsx`, not committed) 1,364.08 kB (gzip 399.68 kB), +169.97 kB (gzip +50.94 kB).
- file-download-in-file-browse D5: the Files tree downloads a file through a plain anchor (`IconButton component="a"`, `href` = `fileDownloadUrl(sessionId, path)`, `download` = the entry name), not `fetch` plus `URL.createObjectURL`. Why: the blob path buffers the whole file in browser memory, which breaks "any size" and shows no browser download progress; the anchor lets the browser stream the orchestrator's raw-bytes route to disk. Consequence for errors: a plain anchor cannot read the response, so a 4xx/5xx (403 at the ingress, 404, 409 `agent_not_ready`, 502) is shown by the browser's own download UI or error page, never in the Files panel. Accepted because the file was just listed by the same agent choice (no `agent_id` is sent). The icon shows for `type == "file"` and for a symlink with `target_type == "file"` only; its click calls `stopPropagation` so it neither opens the preview nor selects the row; the row's name element has `flex-grow: 1`, which keeps the icon on the right edge.

## 2026-10-24

- react-resizable-panels `Separator` pitfall (moved from agent-orchestrator MEMORY.md): the library writes an INLINE `flex-basis: auto` (plus `flex-grow: 0; flex-shrink: 0`) on the separator element, which beats a styled `flex: 0 0 4px` shorthand, so a childless separator renders 0px wide and its colour never shows (dragging still works through pointer hit regions). Size it with an inline `style={{ flexBasis: ... }}` (props.style is spread after the defaults), never with a stylesheet `flex` rule. Why recorded: the dividers were invisible in the live UI while every jsdom test passed.
- FilesPanel polling (moved from agent-orchestrator MEMORY.md; amends D25 of the prior web-ui epic: "event-driven refresh plus a manual refresh button; no inotify", user decisions U2, X2): the "Refresh files" button is removed. `FilesPanel` now polls `pollExpanded()` every 3 s while `document.visibilityState` is visible, plus one pass on `visibilitychange` to visible and on every event stream open, and refetches the open preview when its entry mtime or size changes in the parent listing. The stream path (`fileEvents`) stays for instant agent writes. Why: terminal shells, check jobs and any writer outside the agent hooks produce no events, and a tree that loaded in error (409) or missing only recovered by clicking. Still no inotify and no backend or API change: the tree reads the existing files API. No timer runs while the tab is hidden or the panel is unmounted.
